3 · 汇总与边界

等级词处理
A · 一眼能认（9）apple / cat / fish / sun / star / milk / eye / tree / car全部进 P0，无需再改
B · 能认但有歧义（1）banana比改前明显改善，但纯轮廓仍略像弯叶；配合发音与颜色提示足够，真机重点验证这一张
为什么 banana 没给 A：实际渲染出来是三条平行弧线，香蕉的「弯」和「厚」有了，但缺少能锁定「香蕉」的特征（比如成串、剥开的皮、两端的柄与蒂差异），6 岁孩子单独看图仍可能说「叶子」。这已经是纯线稿在不加颜色、不加场景前提下的较优解；要再往上就得靠颜色或场景，属于升 v2 的范畴，P0 不预先加复杂度。
一个仍未解决的共性问题：10 张图全是单色线稿、没有填充。「apple 红红的」「banana 黄黄的」这些颜色线索在图上完全没有，只能靠轮廓与发音、小智讲颜色。
两条路：① 保持纯线稿（最省 Flash，符合「笔画指令」初衷）；② 每笔加 1 字节色号，10 词仍 < 1 KiB，但 wordline-v1 和 word_render.c 要升到 v2。P0 先保持 ①，真机看孩子是否真的需要颜色再决定，不预先加复杂度。
hand 的诚实复盘：先试过「手指加圆头 + 错落高度 + 拇指外张」的改图，渲染出来仍像笔筒 / 试管架 / 栅栏 —— 4 根等宽竖条插在方框里，这个构图本身就难像手。所以不再修图，直接换词 eye：unit-04 里本来就有「眼睛」，20 笔一眼能认，且孩子可以指着自己的眼睛学。代价仅为重生成 2 段发音（已用现成脚本完成）。
本轮没动的东西：words/ 6 单元 60 词零改动（不加音标、不加字段）；网站词库只作为一次性「图案参照源」留在 p0-pack/source-bbyingyu.json；7 屏 UI、状态机、三键映射、PRD 架构、ADP1 / wordline-v1 格式全部保持原样。
