C1 详解：把两个长按键合并成一个

问题

v0.3 有两个长按键（DOWN 长按=菜单、OK 长按=问小智），而真实固件已把「长按 OK」用作全局菜单入口。照搬会让一个键同时承担三件事，孩子和家长都会混。

P0 建议

全机只用一个长按键心智：长按 OK 呼出菜单。v0.3 的「动态首项」优化恰好承接「问小智 / 退出」语义；P0 不碰在线链路也能闭环。

3数据格式与内存预算

线图 · p0_pack.h（775 B）

magic(2B 'WL') + stroke_count(1B) + n×5B
每笔 [opcode, x1,y1,x2,y2]，坐标 0..200
opcode：1=LINE 2=CIRCLE 3=RECT 4=DOT

映射 sx = 40 + x*0.8，sy = 40 + y*0.8，深墨 #202a33 / 线宽 3px。

发音 · p0_audio.h（280.0 KiB）

完全对齐现成 services/audio_clip.h：
magic 0x31504441 "ADP1" + rate(2) + ch(1) + rsv(1) + num_samples(4) = 12 B 头，其后 IMA-ADPCM nibble 流。

16 kHz / mono / 每字节 2 样本（低 nibble 在前）；每词 normal + slow 两版。

内存关键 · 不要用 lv_canvas：160×160×2 ≈ 51 KiB，会压垮 40 KiB 的 LVGL 池。改为自定义 lv_obj + LV_EVENT_DRAW_MAIN 回调里用 lv_draw_line() / lv_draw_arc() 逐笔直绘，描述符放栈，零中间帧缓冲。曲线已用折线近似。

Flash 落位

方案 A（P0 推荐）方案 B（余量不足时）
做法static const 编进 .rodata，Flash XIP 映射、零 SRAMADP1 打成 words.bin 刷分区，esp_partition_mmap 零拷贝读
分区改动无需改 partitions.csv + release.py 六段镜像校验
代价占 app 分区（3 MiB）约 285 KiB多一个镜像段、刷机步骤变多
前提idf.py size 确认余量 > 320 KiB—

audio 分区 0x37a000, 0x80000（512 KiB）现有余量约 227 KiB，装不下 280 KiB 完整发音包，故方案 B 需扩分区或降采样到 8 kHz。P0 先走 A，「换发音不重编译应用」留到 P1。

4页面线稿（7 屏 + 菜单 2 态 = 8 张 · 240×320 竖屏）

沿用仓库「深蓝黑 / 暖杏焦点、圆角外黑」的小智视觉语言；单词模式内部改用纸白底 + 深墨，与对话态形成「切换到学习」的直觉区分。每屏切换只 lv_obj_delete_async(old) + 建新对象，不做整页动画。②′ 是 ② 在单词模式内的「动态首项」状态，不额外算一屏，故共 7 个页面、8 张线稿。

① 日常小智界面 原样 深色圆角、动态形象、声音驱动嘴型、CW2017 电量条。OK 长按 = 呼出菜单（C1）。
② 右侧菜单（对话态） 置顶 「单词模式」第 1 项且默认高亮，呼出后按一下 OK 即进入。菜单给家长用、可带文字。
②′ 右侧菜单（单词模式内） 动态首项 首项换成「返回小智」，并隐藏原末项「返回」，进/出完全对称。
③ 看图 + 二选一（主屏） 重画 线图约 160×160；两图案各 84×52、合计约屏 11%。屏幕上无任何文字。
④ 跟读（P0 占位） 简化 仅提示可以跟着念。跟读评测（ASR 字幕比对）属 P2，依赖在线服务。
⑤ 读对了 / 认识 只给正反馈 大拇哥 + 星星，暖杏高亮，1.5 s 自动进下一词，不需要孩子操作。
⑥ 没读对 / 不记得 零挫败 耳朵 + 循环箭头 + 喇叭，播 *_slow.adp1 后回主屏；OK 短按可再听一次。
⑦ 问小智（P0 = 返回对话态） 降级 顶部缩略给家长看。「讲完自动回」属 P1/P2；P0 用 NVS 记住 wordmode:index，回来接着当前词。

/* components/core/ports/include/hal/hal_button.h（真实） */

模式按键语义
对话态 ①OK 短按开始 / 结束对话（原固件）
对话态 ①OK 长按呼出菜单 ②（复用现成，C1）
菜单 ②/②′UP / DOWN 短按上 / 下移焦点
菜单 ②/②′OK 短按执行当前项
单词模式UP 短按认识（拇指）
单词模式DOWN 短按不记得（问号）
单词模式OK 短按再听 / 结束跟读 / 跳过结果
单词模式OK 长按呼出菜单 ②′ → 返回小智
事件选择：HAL_BTN_PRESS 是「按下即触发、低延迟」，HAL_BTN_CLICK 有约 180 ms 去双击窗口。图案反应用 PRESS 求跟手，菜单执行用 CLICK 避免误触；长按后的松手不得再触发第二次操作（XIAOZHI_BUILD.txt 第 6 条既有约束，沿用 app_plays_button() 裸手势转发）。孩子平时只碰短按，永远不进菜单、不选单元、不看文字。
